## 1. 研究模式

- **基线模式**：不存在历史报告时，建立第一份完整报告和初始跟踪清单。
- **增量更新模式**：存在历史报告时默认使用。读取稳定最新报告、研究轨迹和未关闭事项，更新新证据影响的部分，再生成完整快照。
- **全量重建模式**：年报、会计更正、重大转型或用户明确要求时使用。重新核验全量关键数据，但仍须与上一版比较。

不要把沿用旧报告理解为直接复制。已确认且未过时的事实可以继承；行情、估值、最新公告、监管状态和报告期必须重新核验。

## 2. 版本与真相来源

- 带日期时间的 Markdown/HTML 是不可变的历史真相来源。
- `_最新.md` 和 `_最新.html` 是方便阅读的派生副本，可以在成功发布后原子替换。
- `.research/state.yaml` 是可重建的机器索引，不得成为唯一真相来源。
- `研究轨迹.md/html` 是从历史快照重建的人类可读索引。
- 同一版本的 Markdown 与 HTML 必须来自同一 Markdown 内容。
- 发布失败时不得刷新 `_最新`，避免最新版本指向不完整产物。

## 3. 结论迁移

比较以下四个固定维度：`基本面判断`、`财务质量`、`估值状态`、`财务造假风险初筛`。

内部研究轨迹与状态索引对每个维度记录：上次结论、本次结论、变化级别和证据。正文 3.2 只展示实质变化；无变化时一句话说明。样式或字段识别等技术修复仅记入内部研究轨迹。变化级别只使用 `不变 / 微调 / 上调 / 下调`。无法可靠判断方向时使用 `微调`，不要伪造精确评级迁移。

预告与正式报告必须形成证据链：

1. 预告发布时保存预告 PDF，结论注明未经审计及缺失的现金流和资产负债表信息。
2. 预告修正时保存新旧两个 PDF，并在资料索引中保留两者，不覆盖旧文件。
3. 正式报告发布时做预告兑现检查，说明实际值是否落在区间、现金流和资产负债表是否支持预告阶段判断。

## 4. 跟踪事项

每个跟踪事项包含：事项、首次提出日期、上次状态、本次证据、当前状态、下次验证时间或量化触发条件。

状态仅使用：

- `待验证`
- `部分验证`
- `已验证`
- `已证伪`
- `已关闭`

未关闭事项必须进入下一版。关闭时说明依据，不能因为报告重新生成而消失。

## 5. PDF 归档

归档实际用于重要判断的正式披露 PDF：年度/半年度/季度报告、业绩预告及修正、审计报告、问询及回复、重大合同/订单、监管公告。

执行要求：

1. 优先公司、交易所或法定披露平台；第三方镜像仅作官方源不可用时的后备。
2. 下载后验证 `%PDF` 文件头；可用 `pdfinfo` 时进一步验证页数。
3. 计算 SHA-256；相同内容只保存一份，多个来源 URL 合并进同一索引项。
4. 内容不同的修订版必须另存，不按标题覆盖。
5. 文件名使用 `<公告日期>_<报告期>_<文档类型>_<公告标识>.pdf`，无法确认的字段写 `日期待核验` 或 `期间待核验`。
6. `资料索引.md` 至少记录标题、类型、期间、公告日期、原始 URL、本地文件、哈希、页数、下载时间和引用报告。
7. 报告优先引用本地相对路径并注明页码；资料索引保留官方 URL。
8. 只有网页而无原始 PDF 时保留网页 URL，不把网页打印成伪“原始 PDF”。
9. 下载或校验失败时记录失败状态和原因，不生成空 PDF，不声称已经归档。

## 6. 发布顺序

1. 读取上一版和未关闭事项。
2. 收集并归档本次使用的正式 PDF。
3. 写完整 Markdown，加入本次变化表和有状态跟踪表。
4. 校验固定结论字段、章节、报告期和本地引用。
5. 写不可变时间戳 Markdown 快照。
6. 从该快照渲染对应 HTML。
7. 两者成功后原子刷新 `_最新.md/html`。
8. 重建研究轨迹和 `.research/state.yaml`。

## 7. 历史迁移

- 发现已有日期报告时，不修改其正文、不重命名、不删除。
- 按文件名日期时间排序；格式较旧、无法提取的字段标为 `未结构化`，不得猜测。
- 从最新历史 Markdown 建立 `_最新`；对应 HTML 缺失时才重新渲染。
- 从所有可识别历史报告重建研究轨迹。
- 回补历史 PDF 时只处理报告中已经引用的正式披露 PDF；媒体、行情和普通网页不批量下载。
